# Implementation Notes: 回到手帐

依据：`design-review.md`（设计评审与方向指引）。本轮把上一轮的「功能清晰的工具软件」收回成「安静的笔记本」。版本号保持 alpha.2 不变。

## 去掉的东西

- 标题栏副标题 "a little space for your day"：只保留在 `--help` 输出里。
- 面板标题里的快捷键 `[s]` `[t]` `[f]`、条目计数 `1/1`、`>` 选中符。
- 底部三行快捷键提示：收成一行。用户权衡后决定这一行保留当前面板的基本操作提示（编辑时换成便签的按键），Saved 这类消息只短暂顶替一秒半（取消不提示）（`App::say` 与 `status_line`），然后自动回到提示；右下角保留一个 `?`。
- 月历标题里的 `y Year`、日期栏里的 `[y Year] [g Date]` 按钮、年视图的翻页按钮和图例。
- 空面板里的操作提示（"n Add a todo" 等）：空白就是空白。
- 月相后的 "(approx.)"：说明放进 Help 和 README。
- 月相的饼图字形（●◔◐◕○◑）：用户认为不合适，改为只用文字。终端应用无法嵌入字体，字形完全取决于用户终端；Nerd Font 的 28 个月相字形效果最好但依赖用户安装，emoji 会引入彩色且各终端不一，Sixel 或 Kitty 图形协议能画真图但偏重且需回退。将来在配置里提供字形集选项。月相计算本来就是纯离线的（平均朔望月加 NASA 基准新月），要更准可离线实现 Meeus 算法或嵌入月相表，不需要联网。
- 标题栏两行收成一行：`09-11 (金) · day 254 · New moon`，日期只保留月日（与 Hobonichi 一致），年份由月历标题承担；省出的一行给左列面板。

## 加上的东西

- **按时间排列的 schedule**（`src/schedule.rs`）。逐条添加，按时间排序展示，每条首行在 gutter 里显示 `HH:MM`，同一时刻的多条归到一个时间标签下，多行内容跟在条目后面。`n` 新建：当天默认当前时刻，光标停在某条上时默认同一时刻（自然归并），其他日期默认 09:00；Enter 编辑光标所在条目，`d` 删除，Up/Down 按条目移动。在最后一条上继续按 Down（或 j）直接新建，当天自动填入当前时刻，todo 同样；滚轮不触发。时间输入宽松（`journal::parse_time_input`）：`9`、`930`、`9:30`、`0930` 都能读。面板高度随内容增长，其余空间留给 free memo。
  - 曾实现过带 6/9/12…刻度的时间标尺（评审文档的理想方案），用户实测后认为混乱：两套 gutter 标记混杂、空刻度占八行却不承载内容、在标尺上选位置既有操作负担又不精确。故改回逐条添加加时间排序展示。
- **就地书写，不离开页面**。编辑不再切到全屏表单：schedule 在光标那一行弹出一张圆角小便签，标题就是时间，Tab 把光标移到标题里改时间；todo 在对应行弹便签；free memo 直接在面板内编辑。页面其余部分保持可见，保存、取消等按键提示和错误信息放在底部那一行。用户反馈：全屏编辑与主页面割裂，右下角显示的时间与时间轴对应关系令人困惑；两者一并解决，右下角的时间显示已去掉。
- **年历墨迹**：有日记文件的日期数字后带一个 `·`，日视图月历同样。数据来自 `Store::written_dates` 扫描目录，保存后即时更新。
- **每日一言轮换**（`src/words.rs`）：内置四十条公版短句按日期轮换；日记目录下的 `words.txt` 每行一条可整体替换。
- **翻页节奏**：切换日期后页面先空白约 45 毫秒再落墨（`App::turning`，主循环在此期间以 30 毫秒轮询）。
- **首次启动引导**：日记目录里没有任何日记文件时启动即显示 Help 覆盖层，之后靠 `?`。
- **月色**（`src/theme.rs`）。参照 Hobonichi 每月一色的印刷方式：十二个和風月名各配一个和色（睦月一斤染、如月勿忘草色、弥生撫子色、卯月若葉色、皐月藤色、水無月白群、文月浅縹、葉月刈安色、長月半色、神無月洗柿、霜月白茶、師走柳鼠）。选色原则：作为页面的印刷色，必须柔和、低饱和、中高明度，退在书写内容后面；深红、深紫这类抢眼的颜色一律不用；相邻月份颜色略有近似可以接受，不追求十二色完全区分，按打开日期所在月自动切换。用色规则：页面「印」上去的东西用月色（所有面板框线、面板标题、便签框、月历标题、今天的日期（月色反色小标签，与当前面板标题同款）、月历面板标题里的和風月名，如 `2026-09 · 長月`；标题栏保持 techō），用户写的内容用默认前景色，操作提示、条目时间等小字保持灰色（月相是主要信息，用默认前景色）。年视图里每个月的方块用各自的月色。当前面板的标题反色显示成一枚月色小标签，框线不再加粗（用户认为粗框不美观）；反色不依赖颜色也能辨认。这取代了此前「唯一一处手帐绿」的方案。
- **余白**：所有面板内部左右各留一列。
- **续页记号**：schedule、todo、free memo 内容超出可见范围时，底边框线右端嵌一个月色的 `⋯`；往下滚过后上方还有内容时，顶边框线右端嵌 `⋯`。只在需要时出现，没有计数和滚动条。free memo 就地编辑期间不显示（编辑器自己随光标滚动）。

## 设计判断与偏离

- 评审文档给出的理想方案是「光标可自由移动、由位置推断时间的文本区」，实测后放弃，改为评审文档里的务实折中：先写内容，时间作为便签标题可选调整，条目按时间排序展示。数据模型不变（`### HH:MM` + 缩进正文），旧日记无需迁移。
- 评审文档的布局示意把 schedule 画成占最大面积。实现上采用空时段压缩后，标尺只需约十行，把多余高度硬塞给它只会留下一片死白，所以高度改为随内容增长、上限六成，剩余交给 free memo。这是可逆的判断，改 `schedule_height` 即可。
- 评审文档写「schedule 区单击直接进入编辑」。弹出编辑器的前提下，单击直接弹窗容易误触，本轮单击只定位光标，Enter 才写。将来若做成行内编辑再改。
- 评审文档写「年视图光标定位在今天」。若正在浏览别的年份，打开年视图跳回今天会丢掉上下文，所以光标落在当前打开的日期；`t` 或 Home 跳到今天。
- 没有单独的月视图页面：月历常驻日视图，`y` 直接进年视图，Esc 回日视图。
- 年视图每月方块从 30 列改为 32 列，否则加了内边距后周日列放不下。

## 后续方向

- **多套色彩方案**。Hobonichi 的封面多样是用户选购的重要因素，对应到 TUI 就是可选的主题。月色表在 `theme.rs`，将来在它之上做可切换的方案（配置或命令行参数），月相字形集也放同一份配置。
- 用户反馈：月历里的周日不需要重点展示，不着色。
- **键位模式可配置**。保存键位全局保持一致（Ctrl+S 或 Ctrl+Enter 保存，Enter 换行），不为单行便签单独改成 Enter 保存；将来通过配置让用户切换键位模式。
