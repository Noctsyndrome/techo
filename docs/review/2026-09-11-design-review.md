# techō 设计评审与方向指引

## 核心设计哲学

techō 取自手帳，目标是通过 TUI 实现一个像 Hobonichi Techo 一样随性、受人喜爱的日常记录应用。

Hobonichi 之所以让人喜欢，不是因为功能强，而是因为它把"每一天值得被记录"做得有仪式感又零压力。选择 TUI 作为载体，约束本身就是设计优势——终端天然没有花哨的干扰，和手帐的"一张纸、一支笔"有相似的克制感。

**最高优先级的设计原则：如果一个元素不是用户自己写下的内容，它就需要证明自己有资格出现在屏幕上。**

时间刻度可以——它是空间参照。日期可以——它是"今天是哪页"。每日一言可以——它是小确幸。但操作提示、计数器、tagline、选中符号，它们服务的是软件的可学习性，不是用户的日常体验，应该尽可能隐到背景里去。

每想加一个 feature，先问：这会让用户更想打开 techō 写点什么，还是只是让它更像一个 productivity tool？

---

## 关于框线与余白

TUI 的框线（box-drawing characters）是终端应用本身的醍醐味，就像 Hobonichi 的方眼格子是纸质手帐的醍醐味一样。**框线保留，这是 TUI 媒介的质感，不是多余的装饰。** techō 是在终端里做手帐，不是在终端里模拟纸。

在保留框线的前提下，余白仍然重要——框线围出的区域内部应该有呼吸空间，不要把内容贴着边框塞满。让框线做好"划分区域"的工作，让区域内部保持舒展。

## Schedule 区的交互

### 问题

"逐个添加条目，指定时间"——这个交互模式是反手帐精神的。Hobonichi 上你从来不会"创建一个条目"，你只是拿起笔在某个位置写字。"添加"是数据库思维，"书写"才是手帐思维。

### 设计目标

让 schedule 区的交互从"录入条目"变成"在时间旁边写字"。

### 推荐方案：带时间标尺的文本编辑区

把 schedule 区当作一个带时间标尺的文本编辑区，而不是一个条目列表。

左侧 gutter 固定渲染时间刻度（6, 9, 12, 15, 18, 21, 0, 3），刻度之间有若干行的纵向空间。主区域是可自由移动光标的文本区。用户把光标移到大约 12 点的位置，按下写入键，直接打字，文字就出现在那里。时间不是用户"指定"的，而是由光标的纵向位置隐式推断的。

视觉效果示意：

```
  6 ┈
  9 ┈  morning run
 12 ┈  lunch with K
       tried the new ramen place,
       not bad actually
 15 ┈
 18 ┈  grocery
 21 ┈  read chapter 3
  0 ┈
  3 ┈
```

**时间精度：** 光标在 gutter 刻度之间移动时，状态栏里淡淡地显示推断出的时间（如 ~10:30），但这个时间不作为条目的强属性，只是辅助感知。用户不需要在意它准不准。

**空间伸缩：** 没有内容的时段压缩为一行刻度，有内容的时段按实际行数撑开。既保持时间线的整体感，又把空间给了需要的地方。

### 务实的折中方案

如果上述方案实现成本太高，保留"添加条目"的数据模型，但改变交互表面：

- 不要让用户先选时间再写内容（表单思维）
- 让用户先写内容，再可选地标注时间
- 流程：光标停在 schedule 区某处 → 按 `e` → 弹出内联编辑 → 直接写文字 → 回车确认 → 时间从位置推断，用户可接受默认值或微调

关键区分：**"写"是第一动作，"归类到几点"是可选的后处理。**

## 日视图的布局结构

Hobonichi 的每一页都有固定的信息结构：左侧是时间轴 + 书写区，右上角是 todo 勾选框，右下角是当月月历，底部是每日一言。这些不是附加功能，是页面的一部分。

**todo 和月视图在日视图中常驻显示，不做成 overlay 或抽屉。** 理由：

- Hobonichi 每页（双页展开时至少一侧）都保证月历可见，TUI 是单屏，更需要月视图常驻来承担日期导航的锚点作用
- todo 是 Hobonichi 的一等公民，每页右上角都是它的位置。打开手帐第一眼就该看到今天要做什么，藏起来就失去了提醒价值

日视图的空间分配参考 Hobonichi 单页布局：

```
┌─ header ──────────────────┐ ┌─ todo ──────────┐
│ 日期 · 星期 · day N       │ │                  │
│ 月相等微信息               │ │                  │
└───────────────────────────┘ │                  │
┌─ schedule ────────────────┐ │                  │
│                            │ └─────────────────┘
│  （主要书写区域，占最大面积）│ ┌─ month ─────────┐
│                            │ │                  │
│                            │ │                  │
│                            │ └─────────────────┘
└───────────────────────────┘ ┌─ words ──────────┐
┌─ free memo ───────────────┐ │                  │
│                            │ └─────────────────┘
└───────────────────────────┘
```

schedule 和 free memo 占左侧主体空间，todo、月视图、每日一言占右侧窄栏。

## 日期切换与翻页感

翻日的手感很重要。左右箭头或快捷键切换日期时，如果能有一个极短的过渡（哪怕只是清屏重绘的节奏感），会比瞬间跳转更像"翻页"。

## 年视图

年视图的角色是"地图"——让用户知道自己在一年里的什么位置，也让用户快速翻到某一天。

**有书写痕迹的年历：** 有日志内容的日期带微妙标记——数字用稍亮的前景色，或数字后缀一个小点。不是 GitHub contribution graph 那种激励暗示，而是像翻开一本用了半年的 Hobonichi 时从侧面看到的墨迹厚度。它不评判你。

**导航模型：**

- 日 → 月 → 年，每一层都可直接跳到另一层
- `m` 切月视图、`y` 切年视图、Enter 永远是"进入这一天"、Esc 永远是"回上一层"
- 年视图里光标定位在今天，方向键在日期间移动，跨月自然流转
- 支持翻年（查看去年的记录）

---

## 鼠标支持

参考 herdr 的思路：mouse-native 但 keyboard-first。完全通过键盘操作，但也支持鼠标点击。

**鼠标对 techō 的各区域：**

- **Schedule 区：** 单击定位光标位置，直接进入编辑。鼠标最大优势是空间寻址——用户脑子里想"下午三点的事"，眼睛看到 15，手点过去就好
- **月视图 / 年视图：** 点击日期直接跳转到该日的日视图
- **Todo / Free memo：** 点击聚焦，点击条目编辑
- **滚轮：** 滑动 schedule 内容

**关键约束：**

- 不做 hover 效果，保持界面沉静
- 两套输入共享同一个状态模型（光标位置、焦点面板、选中状态），鼠标和键盘只是不同的输入源
- 用户可随时混用，不存在"鼠标模式"和"键盘模式"的区分
- 不要让鼠标支持的需求污染键盘体验的纯粹性

## 界面元素评审（针对 Codex 修改版）

以下是对 Codex 修改后界面的具体问题梳理。核心问题：把一个"安静的笔记本"改成了"功能清晰的工具软件"。每个改动单独看"有道理"，叠加起来摧毁了 techō 最核心的品质——克制。

### ✗ 副标题 "a little space for your day"

Hobonichi 封面上不会印 "a notebook for your life"。产品的气质应该通过使用体验传递，不是通过标语宣告。这行字每天都出现，第二天就变成了视觉噪声。

**处理：移除。** 如果保留 tagline，放在首次启动的欢迎页或 `--version` 输出里。

### ✗ 面板标题里的快捷键提示 `[s]` `[t]` `[f]`

把每个面板变成了按钮标签。"schedule" 本身就够了，不需要 "schedule [s]"。用户不需要在每个面板上被提醒"按 s 来这里"。

**处理：移除标题中的快捷键标注。** 这是 Help 页（`?`）的职责，不是界面常驻元素。

### ✗ 条目计数 "1/1"

不需要时刻知道自己有几条 schedule 条目。

**处理：移除。**

### ✗ `>` 选中指示符

Schedule 面板标题前和条目前都有 `>`，重复表达同一件事。`>` 在视觉上很重，在每一行前面制造"这是列表项"的暗示，把自由文本变成了菜单。

**处理：选中状态用高亮或微妙的颜色变化表达，不使用额外字符占位。**

### ✗ 底部三行状态栏

三行快捷键提示占掉终端宝贵的纵向空间，大部分快捷键用户学会后再也不需要看到。

**处理：** 默认只保留一行，只显示当前上下文最相关的操作提示。其余收进 `?` Help。更理想的状态——状态栏默认只显示日期和当前聚焦面板名，快捷键提示只在用户停顿或按下"发现"键时短暂浮现。

### ✗ 月历标题 "2026-09 · y Year"

`y Year` 是操作提示，不是内容。

**处理：移除快捷键提示，只保留日期。**

## 其他细节

- **色彩：** 用 Hobonichi 的绿色 accent 作为唯一彩色点缀（今天的日期、周日标记），其余保持素色
- **Day N（今年第几天）：** 保留，这是 Hobonichi 的特征
- **Words（每日一言）：** 维护每日轮换的语录库，让每天打开 techō 都能看到不一样的一句话。数据源可考虑：公版文学摘句、历史上的今天、用户自定义
- **月历高亮今天：** 用绿色 accent，克制的一个点
- **数据存储：** 每天一个 md 文件，可 grep、可 git 管理、换工具不丢数据
- **状态栏：** Hobonichi 的纸上不印操作说明。新用户引导做成首次启动 overlay，之后尽量隐去
