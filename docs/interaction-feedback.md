# 首个可用版本：交互测试反馈

记录日期：2026-09-11。测试版本：`0.1.0-alpha.1`（`5749802`）。
环境：独立 Windows 终端中的 PowerShell 7。以下为用户实际测试反馈；当前仅记录，尚未修复或验收。

## UX-001：板块切换提示难以理解

- 状态：待处理。
- 现象：底部 `s/t/f: focus` 未说明各按键对应哪个板块，也未清楚表达“切换当前操作板块”；用户无法立即理解其含义。
- 影响：用户难以发现板块切换方式，以及后续按键会作用于哪里。
- 改进方向：使用明确的操作描述，展示按键与板块名称的对应关系；可在板块标题上显示快捷键。具体文案与样式待设计。
- 验收要求：首次使用者无需理解 focus 术语，即可知道如何切换到日程、待办、自由笔记，以及各快捷键的对应关系。

## UX-002：当前操作板块缺少明显的视觉标识

- 状态：待处理。
- 现象：从日程切换到待办后，底部操作提示由 Schedule 变为 Todo，但板块标题和边框看不出明显区别；空待办区也没有清楚的选中状态。
- 用户截图证据：切换前后各板块均呈灰白边框，用户难以从内容区域判断当前操作板块。截图只用于确认现象，尚未确认颜色未显示的原因。
- 影响：用户无法确信切换是否成功，也不易判断新建、编辑等操作的作用范围。
- 改进方向：在当前板块标题或边框提供持续、醒目的标识，并增加不依赖颜色的文字或符号提示；后续排查现有颜色样式在实际启动环境中的表现。
- 验收要求：在日程、待办和自由笔记之间切换时，不看底部提示也能立即辨认当前板块；空内容及无颜色显示时仍能区分；同一时刻仅一个板块显示当前操作状态。

两项反馈来源：用户提供的日程与待办状态截图，以及实际操作描述。后续修复需在独立 Windows 终端中进行人工验收。

## UX-003：支持鼠标操作，首先实现点击选择板块

- 状态：已明确需求，待实现。
- 用户要求：techo 像 herdr 一样，作为 TUI 也应支持鼠标操作；第一步支持鼠标选择板块。herdr 是用户给出的交互参考，本记录未核查其具体实现。
- 首步范围：鼠标左键点击日程、待办或自由笔记板块，即切换当前操作板块；保留键盘切换方式。
- 交互要求：点击板块标题、边框或内容区均可选择该板块，包括空内容区域；鼠标与键盘切换共用同一选中状态，并同步更新板块视觉标识与底部操作提示。
- 验收要求：点击任一可操作板块后，后续新建、编辑等键盘操作作用于该板块；切换状态满足 UX-002 的可见性要求；窗口缩放后点击区域仍准确；点击格言等非操作区域不误选其他板块。月历按 UX-005 承担日期导航，不作为普通内容编辑板块。
- 待设计边界：编辑弹窗打开时的鼠标行为需明确，不能因点击底层板块而丢失编辑草稿。
- 后续范围：鼠标支持是产品明确方向；条目点击、滚动、双击编辑等其他鼠标能力尚未确定，本条不将其列为首步验收要求。

## UX-004：重新评估 schedule 的布局与时间选择交互

- 状态：已记录问题；用户后续提出条目式新增方案，作为当前设计方向，尚未实现。
- 用户反馈：多行记录会影响后续排版；小时切换操作不明显。此前未找到满意的呈现方案，应考虑重新设计，同时保留底层 schedule 的出发点。
- 参考：用户提供的纸质日手帐图片，具有纵向时间刻度和自由书写网格。该图片是设计参考，不是当前程序问题的运行截图。
- 已明确约束：保留围绕一天的时间组织记录的 schedule 语义；重新设计呈现和操作方式，不因终端布局限制而取消时间关联。
- 设计判断：现有布局把全天压缩为固定高度，再在时间对应的行上显示可变长度文本，导致时间位置与文本所需空间发生冲突。不能仅靠调整行距或截断文本解决整体可读性问题。
- 当前方向（用户提出）：schedule 采用类似 todo 的插入添加机制，新增时指定明确的时间与事项；主界面只展示已添加的记录，不再铺满全天空白时间刻度。
- 展示方向：按时间顺序显示已有条目，每条清楚显示时间与事项；新增不再依赖在全天时间轴上移动光标。多行正文的预览、展开方式待设计，须满足下述可读性要求。
- 空间分配：压缩 schedule 的默认占用空间，把更多位置留给 free memo；具体比例或是否随条目数量调整尚未确定。记录较多时应可滚动访问，避免持续挤压 free memo。
- 时间操作：新增表单中明确填写时间和事项；具体键位、时间输入方式、条目修改交互待设计。与 todo 采用一致的新增和选择习惯，同时保留 schedule 的时间语义。
- 现有语义基线：当前实现按 04:00 至次日 04:00 排序，凌晨时间带次日标记；本次反馈没有要求改变该日界规则，设计时应明确保留或另行讨论。
- 待验证标准：多行和长文本不覆盖、混淆后续记录的时间归属；准确时间与当前选中项清楚可见；用户能发现如何新增指定时间的记录及修改时间；长内容可完整访问；小窗口下仍可操作。
- 范围边界：本条不默认引入持续时长、时间冲突检测、重复日程或提醒功能。先解决现有时间记录的展示与选择问题。

## UX-005：整年视图与快速日期跳转

- 状态：已明确需求，待设计与实现。
- 用户要求：能够通过月视图或其他操作进入整年视图，快速跳转到其他日期。
- 参考：用户提供的十二个月全年日历图片，用于说明整年浏览和日期选择的方向；具体网格比例、配色及按钮不是已确定的实现要求。
- 已明确范围：提供整年视图和可发现的进入方式；可以选择其他日期并打开该日手帐，查看和编辑对应日期的 schedule、todo 与 free memo。
- 与既有需求衔接：月视图从静态展示扩展为日期导航入口；日期导航应兼容键盘与鼠标，入口与当前选择状态须清晰可见。
- 建议交互（细节待定）：从月视图的明确入口或快捷键打开年视图；选择日期后回到该日手帐；支持切换年份及快速回到今天。整年视图可用独立页面或大弹层，具体形式待设计。
- 布局要求：适应终端尺寸；十二个月无法同时清晰显示时，采用滚动或分页等方式，保证所有月份和日期均可访问，不强行压缩到不可读。
- 数据要求：不同日期的数据正确隔离；跳转前妥善处理未保存编辑，不能静默丢失草稿。单纯浏览年历不应批量创建空白日记文件。
- 验收要求：无需逐日翻动即可跳到远处日期；跨月、跨年及闰日选择正确；所选日期与打开的手帐日期、内容一致；键盘和鼠标均能完成导航；取消选择可返回原日期且保留编辑内容。
- 待定细节：入口位置、键位、单击或确认后跳转的方式，以及今天、当前打开日期和导航选中日期的区分样式。

## UX-006：日期栏加入月相信息，保留手帐的日常氛围

- 状态：已记录设计需求，具体信息与样式待设计，尚未实现。
- 用户反馈：Hobonichi techo 顶栏日期中包含月相等信息，这也是其独特趣味与吸引力的来源之一。此处记录用户给出的设计参考，未独立核查该产品各版本的具体栏目。
- 设计意图：日期栏除显示日期和星期，也通过月相这类与当天相关的细节表达时间的变化，保留纸质手帐的日常氛围与趣味。
- 首步方向：在日期栏中加入与当前打开日期对应的月相信息；与 UX-005 联动，跳转日期后同步更新，不能始终显示系统今天的月相。
- 呈现建议（待定）：采用紧凑月相符号，并视空间提供名称或说明；应验证实际终端中的字形、宽度与可辨认性，不能仅依赖未经验证的 emoji 显示效果。
- 数据要求：月相须有明确的计算或数据依据，不以随机或固定装饰图案替代；实现前确定日期、时区及取样时刻的约定，避免对近似结果暗示过高精度。
- 范围边界：“类似月相的信息”所包含的其他栏目尚未明确，不默认扩展为天气、节气、节日等整套功能。
- 验收方向：月相信息与所选日期一致；显示紧凑、可读，日期与星期仍清楚；切换日期和缩放窗口后布局正常。具体算法和代表日期校验在实施方案中确定。
